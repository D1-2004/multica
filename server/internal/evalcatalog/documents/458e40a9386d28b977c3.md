# D 包：附件理解、图片、引用定位与轻反馈

> **验收与实现方针：**先读 [Step 0](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2F00-step-0-environment.md) 与 [交付标准](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2F10-delivery-standard.md)。本包的内部API/表结构/阈值/步骤是参考路线，可由主代理协调优化；业务结果、权限、幂等、恢复、真实证据及已合入公共合同必须保持。

> **执行方式：**D1文本与资源来源先交；D2视觉输入在模型能力与预算合同稳定后接；D3引用/反应最后接。后端下载库和DTO由D，模型/Host/控制接缝由P/I。

**目标：**理解用户当前发来的文件与真实图片；安全理解“刚才那条”引用；reaction和致谢有自然轻反馈而不意外触发任务。

## 1. 文件所有权与边界

拟新增：`handler/employee_message_resources.go`、`employee_message_references.go`、`employee_reactions.go`及对应测试；可提取纯资源DTO/校验到独立internal包。已有原生DWS client与安装身份服务复用，不复制上传SDK。

必读：`dwsclient/{sdk_ops,message_file}.go`、当前native subscription解码、DispatchMessage/ReferencedMessage真实类型、`employee_recent_context.go`、`employee_stop_task.go`、模型registry与请求journal。Gawk session/task_addressing指导关联；图片提供方/工具需从当前实际装配核对，不能由“Gawk支持”推断本仓已支持。

引用消息里的旧命令不是新授权。当前外层用户指令可以授权读取已核实引用或控制对应自己的Task，须明确外层意图与Task映射。

## 2. D1：文本资源与来源DTO

Host提供的资源引用必须至少绑定source receipt、provider message ID、canonical scene、requester、resource ID/type和当前读取权限。图片/附件只来自当前或确切授权引用消息的own resources；正文解析出来的URL与quoted resources不能证明当前附件。

建议起始限制：每消息最多4个文件/2张图片，单文件≤10MiB，前台文本提取总≤16KiB，超限显式partial/unavailable。类型先支持UTF-8 txt/md/csv/json；PDF/office/压缩包不在D1保证内。恶意扩展名、MIME不符、损坏编码、路径穿越拒绝；signed URL只在可信DWS下载client内部使用，不给模型/日志。

接口结果建议：state available/partial/unavailable/unsupported、资源stable ref、Host content hash、text或像素引用、提取范围、bytes/截断原因。下载外部I/O在事务外，保存快照前重验权限和lease；缓存复用仍重验scope、源消息和授权。小文本可以PG快照，大不可变对象用现有OSS及来源metadata，不存node-local路径作恢复事实。

- [ ] 写超量、超大、损坏/类型不符、UTF8边界和partial区别；随机代号只在文件内，模型请求确有原文与引用。

## 3. D2：真正视觉能力

先列出当前模型链/Runtime工具实际支持的image input能力，不按模型名字猜。视觉需求需要显式配置并经readiness校验的vision路径；共享Coordinator/Employee模型设置不能被私自换成另一默认模型。

两条可用接法：

1. 当前配置model支持multimodal：原Loop native request带真实像素/可信内部media内容，属于同wake实际≤3次请求；request normalization、journal、cache replay和Langfuse保存必要结构/资源hash，秘密URL脱敏。
2. 配置了独立执行侧视觉工具：明确派后台Task，视觉provider调用在agent_task观测并单独预算；前台告知正在处理，不能把隐藏tool模型算成“零调用”。使用已有执行器，不新增图像理解executor。

没有可用vision路径时准确说明暂不支持；这个负例通过不等于“完整图片能力已交付”。S4退出门槛要求至少一条实际vision路径就绪并完成真实像素和图形关系验收。OCR只算文字提取，不替代视觉理解。

- [ ] 写unsupported模型不接image且无伪成功、图片权限/限额、journal恢复不重复下载/新请求、hash与真实发送媒体一致。
- [ ] 测两轮文本引用+图像问题时上下文和角色保留，未配置fallback不能静默降成看不到图却继续猜。
- [ ] 真实IM输入包含问句未出现的文字与几何关系，记录实际provider请求类型、输入资源hash及usage，不仅tool名称。

## 4. D3：引用Task、reaction与Quiet

**引用定位：**Host维护发送message ID→Task/Run/source/delivery anchor的可信映射；回读确认provider message/cid/actor。不按quoted正文或任意UUID猜Task。当前outer“继续这个/停止这个”的source quote + 同requester/scene/tenant + 本wake fresh read_ref + version仍是效果授权；引用只定位对象。

现有stop_task/continue_task会拒绝ReferencedMessage，扩大支持时显式新工具合同/marker，由I按读者先上线。老job重放保持旧拒绝；多人/多候选及无法核实引用就澄清，不自造映射。steer已有普通引用语义不能被全局resource filter误删。

**reaction：**优先明确来源reaction_event不授权dispatch/control/memory；一般仅Quiet或简短反馈。有真实provider reaction API时使用existingoutbox持久identity/source/target，按当前账号/消息授权提交并对账；没有该API时只报Quiet已支持，不能声称已送表情。S4要求reaction输入安全通过；原生表情发送作为D3独立子项，提供方不支持时记录外部能力阻断，不伪造发送。基本后端交付可用已验的Quiet/短反馈满足轻反馈，但报告中须明确原生表情发送是否通过。

- [ ] 写可信quote可定位自己的Task、伪造/跨actor/旧Run引用不能误控、outer无控制指令零效果、旧snapshot兼容。
- [ ] 写给旧“停止”命令加reaction、单纯致谢/进度问句零Task/Run/control/memory写入。
- [ ] effect批次预检、provider unknown、重复source/native call和stop屏障/文件静音均不退化。

## 5. 真人验收

RES-01：文本附件藏随机码，问句不含答案，准确答并引用文件。RES-02：真实图片有随机文字和图形关系，两项都正确；核像素提供方请求。RES-03：过大/坏文件/无权限明确失败，无旁读。REF-01：引用已交付Task继续新要求，同Task新Run；引用正在工作的Task停止，核真退出。REA-01：reaction旧命令/致谢不触发副作用；允许时真实表情可回读，Quiet不强凑任务。

复跑JSON、文件仅交付、history指代、同人多Task四组既有门禁。完整交付标注文本/视觉/引用/reaction四项分别的部署与E2E状态，不能只报“附件功能完成”。
