# 最终交付标准与实现优化方针

本文件定义交付结果及必要约束；[Step 0](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2F00-step-0-environment.md)定义环境和协作准入，[总控](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2FREADME.md)组织工作，[I/Q](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2F08-integration-and-release.md)提供检查/发布手册。任务包的方法名、表结构、DTO、具体阈值与测试剧本是参考设计，不能反过来替代本文件的产品验收。

## 1. 方针：结果验收、强模型优化、工程事实兜底

目标是交付像持续跟进工作的同事一样的Employee后端。实现主要参考既有R5/R2架构、当前系统和固定GawkBot机制，主代理/开发模型可以提出更好的实现，并据事实调整拆分与节奏。

模型负责理解指代、关联事项、选择下一步和自然表达。Host负责权限、场域/来源、事务、版本、效果与恢复，验收负责证明用户实际体验与业务结果。不通过强制固定文案、逐字匹配prompt或规定每条消息必须走相同工具顺序来压缩模型优化空间。

采用更好方案时，在合入前写清：解决的问题、相对参考设计的变化、接口/迁移/兼容影响、权限与恢复等价证明、反例及真实验证。影响其他任务的公共合同由主代理协调，不能各代理偷偷改变共同协议。

## 2. 不可破坏的约束与可优化的细节

| 必要约束 | 可自由优化的实现细节 |
| --- | --- |
| Task目标独立于Issue，一次执行不误完成仍有依赖的事项 | 等待状态的具体枚举、投影、版本字段与内部方法名 |
| 唯一可信scene/tenant/principal来源，输入不能提升权限 | Builder拆分、上下文组织、候选排序与澄清策略 |
| PG保存事实、幂等/事务恢复，Redis丢失不丢工作 | PG表/索引布局、缓存方式、批大小、调度接缝 |
| 同一工作不会因重投/并发重复执行或重复新发效果 | intent/outbox的具体数据模型及恢复查询 |
| 停止具有真实退出证明，旧结果与旧目标不越界发送 | 控制接口内部结构、进程观测及状态表达方式 |
| 模型真实调用可审计，保留现有前台≤3次预算和快速首轮能力 | 提示词、口吻、工具schema、读取顺序、无需推理的快路 |
| 不增加隐藏的分类/审核/总结或视觉模型成本 | 合理视觉路径、后端工具选用、后台预算配置与明确记账 |
| 普通结果事实不自动成为继续工作的授权 | 显式后续计划格式、条件编译和有界推进策略 |
| 记忆权限/来源/墓碑和撤回可验证，可信度不由模型自报 | 检索/经验组织、适用性判断、提炼和治理算法 |
| 旧已接受快照/工作不被新部署热改，回退可控 | reader版本/capability选择、波次和开关组织 |

现有20秒子请求/45秒wake、媒体大小、watchdog阈值、最大后续步数8等在包内有当前值或起始建议。除已明确承诺的模型预算及安全/正确性边界外，主代理可以按测量调整配置和实现；需要变更公共行为时记录版本与验收，不能悄悄改变已接受任务。不能把某个固定数字本身当产品完成条件。

## 3. 最终用户/业务结果标准

| 交付能力 | 结果标准 | 必须取得的证据 |
| --- | --- | --- |
| 连续理解与自然交互 | 理解近期相关对话、当前事项和等待输入；正确处理补充/纠正/询问/新工作；歧义时合理澄清，闲聊不误派任务 | 多轮真实IM，含旧冲突历史与指代；实际回复、Task/Run变化和必要调用数 |
| 独立Task与执行 | 同一事项正确延续；真实进度有依据；执行和目标状态区分；Issue仅为可选承载 | Task/输入/Run/queue关联、实际执行输出、无Issue的生命周期 |
| 纠正与停止 | 新要求正确作用于原事项；停止落实到正确工作并确认退出；过时结果不再新发，不因普通补充复活 | 来源/read/version、进程退出证据、后继数量、实际消息及延后观察 |
| 跨场域收集 | 授权对象的答复正确归属/计数，乱序/重投和同人多Task不串，收齐只向获准发起场域交付 | 邀请/源receipt/输入/推进/action链、真实对象答复、其他参与者隐私反例 |
| 定时与外部事件 | 真实到点/合法事件能够按配置执行或判断；暂停/禁用、重复/冲突事件和恢复正确 | occurrence/delivery/source/Task关联，真实到点/签名、实际结果，无重复效果 |
| 执行事件与主动跟进 | 事实可追踪，获授权的后续步骤能推进；等待/无进展表达诚实，跟进有边界 | terminal fact/授权plan/wake，真实活动/等待状态、一次提醒/推进及调用账本 |
| 附件、图片与交付 | 对实际文件/图像内容回答正确；引用定位可信；文件用户可收到并读回；轻反馈不触发旧指令 | 实际资源/像素、未知答案/图形关系、原生message/file回读、内容hash与副作用检查 |
| 场域能力 | 暴露实际可用能力/配置入口，身份与自管理不缺失，执行能力按当前权限可用 | 正确scene链接及生效配置、真实MCP/连接/资源动作，测试项清理 |
| 记忆与进化 | 当前作用域可记/纠正/忘；验证后经验能被后续真实工作使用；共享晋级和撤回合法有效 | 来源/verification/learning/manifest链、新Task实际行为、权限隔离与撤回后不再召回 |
| 可靠性与运维 | 多副本/重启/通知丢失/模型及渠道失败可恢复，结果不重复，问题可定位，兼容发布/回退可操作 | 真实PG/Redis故障回归、必要隔离环境演练、实际版本、trace/log/receipt、runbook |

该表是整体交付方向，具体子项的本轮范围由主代理明确。上游不提供原生reaction或某视觉能力时，记录外部依赖与真实支持范围，和验收负责人明确是否影响本轮范围；不能以桩通过、Quiet或OCR冒称完整原生表情/视觉能力已经交付。

## 4. 如何评价模型结果，避免死板

- 语义与业务事实优先：同义表达、等价正确输出、合理新工具组合均可通过，不要求与样例文案一致。
- 样例case是构造证据的方法，可替换人物、数字、材料和操作顺序，但保留相同风险覆盖。不能换掉触发失败的前提以规避原问题。
- 用户明确要求的JSON、原样输出、文件静音等按格式/交付合同验收；普通回复看准确、清楚、必要、自然，不以固定长度/句式评分。
- 多Task真正歧义时允许澄清；目标和权限已清楚时不反复追问。真实进度不编造百分比/ETA/执行已开始。
- 首轮能完成的应直接完成；必要读取/执行可使用预算内多轮。统计实际请求/耗时/失败，不由少量case宣称p95或“永远首轮”。
- 强模型的优化必须由新增反例、真实体验、成本与恢复证据支撑。提示词变得更长或工具返回“成功”都不是验收依据。

## 5. 实现、合入、发布、验收分别怎样成立

| 阶段 | 必须有的事实 | 不能替代下一阶段 |
| --- | --- | --- |
| implemented | 范围明确、代码/接口/变更可评审 | 不能当本地验证或线上完成 |
| locally_verified | 相应环境真实执行测试，有退出码与反例/故障覆盖，必要DB/Redis未SKIP | 不证明合入后组合和真实模型体验 |
| integrated | 主代理已合入唯一交付分支，依赖/兼容/旧能力回归通过 | 不证明该SHA已发布 |
| deployed | pipeline及实际运行版本/配置确认，对应reader/producer门禁成立 | 不证明实际IM/执行/送达 |
| e2e_verified | 对已部署范围，用户效果、Task/执行事实和观测链均满足结果标准 | 不自动覆盖未实施/未跑的其他能力 |

每轮可以交付一个完整垂直切片。未经团队确认调整的范围仍待完成；已知阻断、未部署或未验证部分显式保留。主代理负责迭代计划，Q独立验证关键结果，团队协助解决外部资源，不要求模型自行猜账号/授权。

## 6. 最终签收与节奏原则

完整后端签收需：当前约定能力范围满足上述结果、既有核心链路不退化、实际交付版本可追踪、兼容/恢复与运行手册可用、环境/测试对象清理有记录、剩余或外部阻断项与验收负责人明确。

安全/权限/错误归属、重复副作用、虚报执行/退出/送达属于阻断项。普通文风、候选方案优劣和可测性能优化允许迭代，不因偏离参考函数名/表名拒收；未达到用户明确格式、静音或正确性要求仍须修复。

主代理每轮先定义结果/风险和验证方法，再安排子代理实现；完成后合入交付分支、集成测试、发布、真实复测。通过后推进下一轮，有问题沿同一链路修复。具体发布大小、并发和日历由实际任务拓扑和资源决定，[README的S1–S6](/evals?tab=evals&doc=docs%2Fplans%2F2026-10-03%2Femployee-loop-backend-delivery%2FREADME.md)是可调整路线，不是固定发布次数。
