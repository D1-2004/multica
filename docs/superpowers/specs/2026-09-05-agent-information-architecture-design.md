# 智能体信息架构简化设计

日期：2026-09-05

## 目标

简化工作区左导航和智能体详情页，让用户能快速区分三类行为：查看智能体的工作状态、定义数字员工、配置技术能力与运行方式。

设计必须满足以下原则：

- “数字员工”是一等概念，拥有独立 Tab。
- 数字员工身份不与钉钉 Bot、飞书 Bot、Slack、企业微信等机器人接入混放。
- 简单来自分组和渐进披露，不来自把相似概念强行合并。
- 每个配置 Tab 只回答一个清楚的问题。
- 不改变现有后端字段、权限语义和保存协议。

## 范围

本次包含：

- 重组工作区全局左导航。
- 重构智能体详情页一级导航。
- 重构智能体配置区的分组和 Tab。
- 新增“数字员工”Tab，并移动现有资料、身份和沟通行为。
- 保留并修正 URL 深链、权限控制、未保存提示和响应式导航。

本次不包含：

- 重做智能体列表。
- 重做智能体创建流程。
- 修改后端 API、数据库或权限模型。
- 重新设计各功能页内部的业务能力。

## 现状问题

智能体详情当前有 6 个一级入口：概览、工作、入站、记忆、能力、设置。“能力”和“设置”下面又分别暴露多个二级 Tab。

随着入站、记忆、OKR、身份、A2A、LLM Trace 等能力逐步加入，原有分类出现了三个问题：

1. 分类维度不一致。“能力”同时包含指令、Skills、MCP、运行设备、机器人集成和身份；“设置”同时包含资料、OKR、权限、运行参数和诊断。
2. 相似概念被混放。数字员工账号、集团员工身份、GitHub 沙箱身份和各类 Bot 都出现在“身份”或“集成”附近，但用途完全不同。
3. 页面同时出现全局左栏、详情顶部 Tab 和配置侧栏三套导航，且配置侧栏为平铺列表，概念数量过多。

## 方案选择

采用“运营与配置分层”方案：

- 日常查看保留为详情页一级入口。
- 所有编辑入口集中到“配置”。
- 配置内部使用可折叠分组，每个功能继续保持独立 Tab。
- 不采用“运营 / 构建”双模式，避免引入新的抽象术语。
- 不采用管理抽屉，避免复杂表单、深链和未保存状态被压进临时容器。

## 全局左导航

### 一级结构

个人入口保持不变：

- 收件箱
- 聊天
- 我的任务

工作区常用入口保持直接可见：

- 任务
- 项目
- 自动化
- 统计
- 网站

新增两个可折叠分组：

#### 智能体与小队

- 智能体
- 小队
- 运行时
- 本机 Runner

#### 扩展

- Skills
- 连接

“连接”复用现有工作区设置中的集成能力，不新增后台模型。工作区“设置”继续作为独立入口。

### 折叠行为

- 当前路由所属分组自动展开。
- 用户可以手动展开或收起其他分组。
- 手动状态只需要保留在当前客户端会话，不新增持久化服务端状态。
- 分组标题使用 `button`，子项使用真实链接；标题提供 `aria-expanded` 和明确的可见焦点状态。
- 选中子项在 hover 时仍保持选中状态可辨识。

## 智能体详情一级导航

一级入口收敛为 5 个：

| 入口 | 回答的问题 | 内容 |
| --- | --- | --- |
| 概览 | 它现在怎么样？ | 当前运行、最近工作、性能和摘要 |
| 工作 | 它在负责哪些任务？ | 分配给该智能体的任务视图 |
| 对话 | 谁在和它说什么？ | Coordinator 入站会话与处理时间线 |
| 记忆 | 它记住了什么？ | 场域记忆、事项关系和记忆开关 |
| 配置 | 它是谁、会什么、怎么运行？ | 全部定义、能力、接入、执行和管理入口 |

“入站”改名为“对话”。“能力”和“设置”不再作为一级入口。

## 配置信息架构

配置左栏采用手风琴：只展开当前 Tab 所属分组，其他分组收起并显示入口数量。分组只负责降低同时暴露的概念数，不合并功能页。

### 身份与目标

| Tab | 单一职责 |
| --- | --- |
| 数字员工 | 员工资料、企业身份、沟通风格与消息处理 |
| 指令 | 每次任务都使用的 System Prompt |
| OKR | 智能体长期追求的目标与关键结果 |

### 能力

| Tab | 单一职责 |
| --- | --- |
| Skills | 为智能体添加可复用的方法、资料和支持文件 |
| MCP 工具 | 配置智能体主动调用的 MCP servers |
| MCP 应用 | 配置智能体主动调用的 Composio 应用；仅在功能开关启用时显示 |

“MCP 工具”和“MCP 应用”不合并，避免把 server 配置和应用授权混为一谈。

### 接入

| Tab | 单一职责 |
| --- | --- |
| 机器人接入 | 钉钉 Bot、飞书 Bot、Slack、企业微信及对应派发消息配置 |
| MCP 接入 | 让外部 MCP 客户端调用此智能体 |
| A2A | 发布和管理 Agent-to-Agent 接口 |

三个入口按调用方向和协议保持独立。“机器人接入”不得展示数字员工账号绑定。

### 执行

| Tab | 单一职责 |
| --- | --- |
| 运行时 | 运行时、模型、思考强度、速度、并发和会话续接；包含 GitHub 沙箱执行身份区 |
| 本机 Runner | 绑定和管理本机执行设备 |
| 环境变量 | 管理运行时环境变量 |
| 自定义参数 | 管理 provider CLI 参数及命令预览 |
| 路由 | 管理 OpenClaw 路由；仅适用运行时显示 |

“运行时”和“本机 Runner”保持独立；“环境变量”“自定义参数”“路由”也不合并。

### 管理

| Tab | 单一职责 |
| --- | --- |
| 访问权限 | 控制谁能看见、使用和管理智能体 |
| LLM Trace | 查看云端智能体的模型调用记录；仅适用运行模式显示 |

## “数字员工”Tab

“数字员工”页使用单列设置页布局，按以下顺序展示四个区块。

### 1. 员工资料

- 头像
- 名称
- 描述

这些字段描述同事在任务、动态和聊天里看见的员工资料。

### 2. 企业身份

企业身份区同时展示两张用途明确的卡片，但不把两类身份解释成同一种绑定：

#### 钉钉数字员工账号

- 用于监听单聊和群聊消息。
- 用于以数字员工账号回复同事。
- 管理消息范围和任务 / 对话 / 自动处理模式。
- 明确提示“不作为沙箱执行身份”。

#### 集团员工身份

- 用于在 Aone Sandbox 中使用 BUC 免登、a1 和 mw。
- 明确提示“不负责接收聊天消息”。
- 只在相应运行时或部署能力可用时展示。

GitHub 沙箱身份不属于数字员工，移动到“运行时”的执行身份区。

### 3. 沟通风格

- 基础人设
- 回复语气
- 人设与语气模板
- 从 System Prompt 抽取人设和语气

这里仅控制聊天表达，不控制是否创建任务。System Prompt 本体留在“指令”Tab。

### 4. 消息处理

- 入站先判断
- 事情完成再判断
- 续接上一轮会话

这些设置共同决定数字员工收到消息后如何响应和保持上下文，不与运行时、模型或机器人授权混放。

## 页面与组件边界

实现应按职责拆分，不复制表单逻辑：

- `AgentOverviewPane`：只负责一级导航、当前 view、可见性和未保存拦截。
- `AgentConfigNav`：由单一配置注册表渲染分组与 Tab，并根据权限、运行时和功能开关过滤。
- `DigitalEmployeeTab`：组合员工资料、企业身份、沟通风格和消息处理。
- `InstructionsTab`：移除 persona / reply tone，只保留 System Prompt 相关编辑。
- `RobotConnectionsTab`：从原 Integrations 中移除数字员工账号和 MCP 接入，只保留 Bot 与派发配置。
- `AgentMCPAccessTab`：承载外部 MCP 调用入口。
- `RuntimeTab`：承载原通用设置中的执行字段及 GitHub 沙箱身份。
- 现有字段控件和查询 hooks 优先抽取复用，不在新 Tab 中重写网络请求和保存逻辑。

配置注册表是 view ID、分组、标签、可见条件和默认入口的单一来源，避免继续维护互相漂移的 `TOP_TABS`、`CAPABILITY_TABS`、`SETTINGS_TABS` 和 ID Set。

## 导航与状态

- 当前叶子 Tab 始终写入 `?view=`。
- 刷新、浏览器前进后退和分享链接恢复同一个叶子 Tab。
- 点击一级“配置”时，若当前已位于配置页则保持当前 Tab；否则优先回到本次访问过的配置 Tab，没有记录时进入“数字员工”。
- 原 `view=identity` 链接和 OAuth 回跳统一迁移到 `view=digital_employee`。
- 其他有效 view ID 尽量保持不变，减少深链和测试迁移范围。
- URL 指向无权限或当前运行时不支持的 Tab 时，回退到该分组第一个可见 Tab；分组无可见项时回退到“数字员工”，并用 replace 修正 URL。
- Tab 可见性在能力查询加载过程中沿用当前避免闪烁的策略。

## 未保存与错误处理

- 所有可编辑 Tab 通过统一 dirty contract 向详情容器报告未保存状态。
- 点击一级导航、配置分组、配置 Tab、浏览器返回或关闭页面时都使用同一套离开确认。
- 保存失败保留当前草稿；错误在字段附近或当前 Tab 内显示，并使用现有 toast 作为补充反馈。
- 身份绑定错误留在对应身份卡片内，不把一张卡片的错误提升为整个“数字员工”页不可用。
- 某个条件能力加载失败时，不影响其他配置组和日常查看页面。

## 响应式行为

桌面端使用固定宽度的配置侧栏和独立内容滚动区。

窄屏不平铺全部配置 Tab，改为两级选择：

1. 选择分组。
2. 选择该分组中的当前 Tab。

页面仍显示当前 Tab 标题，选择控件使用原生按钮 / 弹出菜单语义并支持键盘和可见焦点。

## 测试策略

### 单元与组件测试

- 配置注册表：分组顺序、默认 Tab、view 到分组映射、条件可见性。
- 一级导航：只显示 5 个入口，旧“能力”“设置”不再出现。
- URL：直接打开每个有效 `view`、刷新、前进后退和隐藏 Tab 回退。
- 折叠：只展开当前分组，切换 Tab 自动切换展开组。
- dirty guard：顶部 Tab、配置 Tab、返回和关闭页面均拦截未保存草稿。
- `DigitalEmployeeTab`：包含员工资料、数字员工账号、集团员工身份、persona / reply tone 和消息处理；不包含 Bot、MCP、A2A 或 GitHub 沙箱身份。
- `RobotConnectionsTab`：包含 Bot 和派发配置；不包含数字员工账号或企业身份。
- `RuntimeTab`：包含运行参数和 GitHub 沙箱身份；不包含数字员工身份。
- 权限与功能开关：只读、MCP 支持、MCP 应用、OpenClaw 路由、云端 LLM Trace。
- 响应式导航：窄屏只显示两级选择器，不产生横向 Tab 溢出。

### 验证

- 运行 `packages/views` 中智能体相关 Vitest。
- 运行 TypeScript typecheck。
- 在本地 Web 页面验证桌面和窄屏布局。
- 对比预发页面，确认原有保存、身份绑定、机器人绑定和 OAuth 回跳仍可到达正确位置。

## 验收标准

1. 智能体详情一级导航固定为“概览、工作、对话、记忆、配置”。
2. 配置默认进入“数字员工”，配置侧栏按 5 组折叠展示。
3. 每个现有配置能力都有唯一且可解释的入口，没有功能丢失。
4. 数字员工账号和集团员工身份只出现在“数字员工”。
5. 钉钉 Bot、飞书 Bot、Slack 和企业微信只出现在“机器人接入”。
6. GitHub 沙箱身份只出现在“运行时”的执行身份区。
7. MCP 工具、MCP 应用、MCP 接入和 A2A 不互相合并。
8. URL 深链、条件可见性、权限和未保存保护具备自动化测试。
9. 桌面与窄屏都不同时暴露十多个平铺 Tab。
