# 智能体信息架构简化设计

日期：2026-09-05（2026-09-06 二次修订）

## 目标

简化工作区左导航和智能体详情页，让用户能快速区分三类行为：查看智能体的工作状态、定义数字员工、配置技术能力与运行方式。

设计必须满足以下原则：

- “数字员工”是一等概念，拥有独立 Tab。
- 数字员工身份不与钉钉 Bot、飞书 Bot、Slack、企业微信等机器人接入混放。
- 简单来自稳定展开的目录和有因果关系的渐进披露，不来自把相似概念强行合并。
- 每个配置 Tab 只回答一个清楚的问题。
- 用户可见名称描述用途，不直接暴露 Runner、routing 等实现术语；技术名称只在高级说明或诊断场景出现。
- 用户不需要记住上一层分组才能找到功能：核心入口直达，当前路径和选中状态持续可见。
- 实际不生效的字段不伪装成普通可编辑项；先说明生效条件，再展示依赖配置。
- 不改变现有后端字段、权限语义和保存协议。

## 范围

本次包含：

- 重组工作区全局左导航。
- 重构智能体详情页一级导航。
- 重构智能体配置区的分组和 Tab。
- 新增“数字员工”Tab，并移动现有资料、身份和沟通行为。
- 保留并修正 URL 深链、权限控制、未保存提示和响应式导航。

本次不包含：

- 重做智能体列表。
- 重做智能体创建流程。
- 修改后端 API、数据库或权限模型。
- 重新设计各功能页内部的业务能力。

## 现状问题

智能体详情当前有 6 个一级入口：概览、工作、入站、记忆、能力、设置。“能力”和“设置”下面又分别暴露多个二级 Tab。

随着入站、记忆、OKR、身份、A2A、LLM Trace 等能力逐步加入，原有分类出现了三个问题：

1. 分类维度不一致。“能力”同时包含指令、Skills、MCP、运行设备、机器人集成和身份；“设置”同时包含资料、OKR、权限、运行参数和诊断。
2. 相似概念被混放。数字员工账号、集团员工身份、GitHub 沙箱身份和各类 Bot 都出现在“身份”或“集成”附近，但用途完全不同。
3. 页面同时出现全局左栏、详情顶部 Tab 和配置侧栏三套导航，且配置侧栏为平铺列表，概念数量过多。

## 方案选择

采用“一级入口直达、配置稳定展开、数字员工按状态渐进披露”方案：

- 日常查看保留为详情页一级入口。
- 所有编辑入口集中到“配置”。
- 配置内部的全部分组和功能入口始终展开，每个功能继续保持独立 Tab。
- 数字员工先设置消息判断方式，只在“入站先判断”开启后展示依赖它的人设和跟进配置。
- 不采用“运营 / 构建”双模式，避免引入新的抽象术语。
- 不采用管理抽屉，避免复杂表单、深链和未保存状态被压进临时容器。

## 全局左导航

### 一级结构

个人入口保持不变：

- 收件箱
- 聊天
- 我的任务

工作区入口按用户心智划分为四个始终展开的场域。分组标题只用于建立概念边界，不参与点击或折叠：

### 协作

- 任务
- 项目
- 自动化
- 统计
- 网站

### Agent

- 智能体
- 小队
- Skills

“智能体”是 Agent 场域的主入口：默认使用比同组入口更高的字重和前景色，图标使用轻量品牌色容器；选中时继续使用统一的选中面和高对比度文字。强化应来自稳定层级，不添加“核心”等额外徽标。

### 运行时

- 运行时
- 我的电脑

### 配置

- 设置

“智能体”必须直接暴露，不能依赖用户先理解并展开“智能体与小队”。“本机 Runner”的用户可见名称统一改为“我的电脑”，内部 route、类型和协议名称保持不变。

删除左侧“连接”。钉钉、飞书等工作区级连接集中在“设置 → 应用集成”；智能体自己的机器人接入、MCP 接入和 A2A 继续留在对应智能体配置中。工作区“设置”保持独立一级入口。

所有一级项使用真实链接并提供明确的可见焦点。选中项在 hover 时仍保持选中状态可辨识。

## 智能体详情一级导航

一级入口收敛为 4 个：

| 入口 | 回答的问题 | 内容 |
| --- | --- | --- |
| 概览 | 它现在怎么样？ | 当前运行、最近工作、性能和摘要 |
| 工作 | 它在负责哪些任务？ | 分配给该智能体的任务视图 |
| 记忆 | 它记住了什么？ | 场域记忆、事项关系和记忆开关 |
| 配置 | 它是谁、会什么、怎么运行？ | 全部定义、能力、接入、执行和管理入口 |

“对话”“能力”和“设置”不再作为一级入口。旧 `view=inbound` 不再被识别为有效详情入口，进入时按普通无效 view 回到“概览”，不保留隐藏的平行页面。

## 配置信息架构

配置左栏采用稳定目录：五个分组标题和全部功能入口始终展开，不再出现手风琴、箭头和入口数量。分组只负责建立概念边界，不合并功能页。

视觉上使用低对比度侧栏底色和紧凑但不拥挤的间距。分组标题使用 `text-micro`、中高字重和更弱的前景色；实际 Tab 使用 `text-body`、至少 40px 点击高度和常规前景色，让“目录标签”和“可点击页面”一眼可分。组间距必须明显大于组内间距。当前入口使用浅色选中背景、较高字重和左侧强调标记；hover 不得覆盖选中态。内容区保持单一主滚动面，不通过更多边框制造层级。所有交互项使用语义化按钮或链接、清晰的 `focus-visible` 状态；装饰图标对辅助技术隐藏。

### 身份与目标

| Tab | 单一职责 |
| --- | --- |
| 数字员工 | 员工资料、企业身份、沟通风格与消息处理 |
| 指令 | 每次任务都使用的 System Prompt |
| OKR | 智能体长期追求的目标与关键结果 |

### 能力

| Tab | 单一职责 |
| --- | --- |
| Skills | 为智能体添加可复用的方法、资料和支持文件 |
| MCP 工具 | 配置智能体主动调用的 MCP servers |
| MCP 应用 | 配置智能体主动调用的 Composio 应用；仅在功能开关启用时显示 |

“MCP 工具”和“MCP 应用”不合并，避免把 server 配置和应用授权混为一谈。

### 接入

| Tab | 单一职责 |
| --- | --- |
| 机器人接入 | 钉钉 Bot、飞书 Bot、Slack、企业微信及对应派发消息配置 |
| MCP 接入 | 让外部 MCP 客户端调用此智能体 |
| A2A | 发布和管理 Agent-to-Agent 接口 |

三个入口按调用方向和协议保持独立。“机器人接入”不得展示数字员工账号绑定。

### 执行

| Tab | 单一职责 |
| --- | --- |
| 运行时 | 运行时、模型、思考强度、速度、并发和会话续接；包含 GitHub 沙箱执行身份区 |
| 我的电脑 | 选择一台已连接的电脑，让智能体使用其中的文件和工具完成任务 |
| 环境变量 | 管理运行时环境变量 |
| 自定义参数 | 管理 provider CLI 参数及命令预览 |
| 路由 | 管理 OpenClaw 路由；仅适用运行时显示 |

“运行时”和“我的电脑”保持独立；“环境变量”“自定义参数”“路由”也不合并。页面标题使用“使用我的电脑”，空状态使用“还没有连接电脑”等自然语言，不向普通用户暴露 Runner 概念。

### 管理

| Tab | 单一职责 |
| --- | --- |
| 访问权限 | 控制谁能看见、使用和管理智能体 |
| LLM Trace | 查看云端智能体的模型调用记录；仅适用运行模式显示 |

## “数字员工”Tab

“数字员工”页使用单列设置页布局，先解释消息处理方式，再按状态展示相关配置。

### 1. 入站判断

页面顶部首先展示“入站先判断”主卡片：

- 开启：钉钉和网页消息先由 Coordinator 判断能否直接回复，只有需要工具、查资料或持续跟进的工作才进入沙箱。
- 关闭：每条消息直接进入沙箱执行。
- 保存中的反馈和失败回滚沿用现有布尔设置行为。

当开关关闭时，在主卡片下明确提示“人设、回复语气和完成后跟进仅在入站先判断开启后生效”，并隐藏这些依赖配置，避免出现可编辑但实际不生效的字段。

主卡片通过标题、两行结果说明和状态标签建立层级，不引入新的步骤条或向导。切换后页面只改变依赖区块的可见性，不滚动到其他位置；异步保存期间开关不可重复触发，失败时恢复原状态并给出可执行的错误反馈。

### 2. 员工资料

- 头像
- 名称
- 描述

这些字段描述同事在任务、动态和聊天里看见的员工资料。

### 3. 企业身份

企业身份区同时展示三张用途明确的卡片，但不把三类身份解释成同一种绑定：

#### 钉钉数字员工账号

- 用于监听单聊和群聊消息。
- 用于以数字员工账号回复同事。
- 管理消息范围和任务 / 对话 / 自动处理模式。
- 明确提示“不作为沙箱执行身份”。

#### 钉钉执行身份

- 用于智能体在 Multica 内直接对话时调用 DWS 工具。
- 不创建消息通道或订阅。
- 与数字员工的收发消息账号分别绑定和解除。

#### 集团员工身份

- 用于在 Aone Sandbox 中使用 BUC 免登、a1 和 mw。
- 明确提示“不负责接收聊天消息”。
- 只在相应运行时或部署能力可用时展示。

GitHub 沙箱身份不属于数字员工，移动到“运行时”的执行身份区。

### 4. 沟通风格（仅入站先判断开启时）

- 基础人设
- 回复语气
- 人设与语气模板
- 从 System Prompt 抽取人设和语气

这里仅控制 Coordinator 的聊天表达，不控制是否创建任务。System Prompt 本体留在“指令”Tab。

### 5. 消息处理

- 续接上一轮会话
- 事情完成再判断（仅入站先判断开启时）

“续接上一轮会话”属于沙箱会话能力，始终显示且不受“入站先判断”控制。“事情完成再判断”依赖 Coordinator，只在主开关开启后展示。这些设置不与运行时、模型或机器人授权混放。

## 页面与组件边界

实现应按职责拆分，不复制表单逻辑：

- `AgentOverviewPane`：只负责一级导航、当前 view、可见性和未保存拦截。
- `AgentConfigNav`：由单一配置注册表渲染分组与 Tab，并根据权限、运行时和功能开关过滤。
- `DigitalEmployeeTab`：组合入站主开关、员工资料、企业身份、沟通风格和消息处理，并负责基于 `inbound_coordinator` 做渐进披露。
- `AgentMessageSettings`：拆分主开关、独立的会话续接和依赖 Coordinator 的完成后跟进，避免再次渲染重复开关。
- `InstructionsTab`：移除 persona / reply tone，只保留 System Prompt 相关编辑。
- `RobotConnectionsTab`：从原 Integrations 中移除数字员工账号和 MCP 接入，只保留 Bot 与派发配置。
- `AgentMCPAccessTab`：承载外部 MCP 调用入口。
- `RuntimeTab`：承载原通用设置中的执行字段及 GitHub 沙箱身份。
- 现有字段控件和查询 hooks 优先抽取复用，不在新 Tab 中重写网络请求和保存逻辑。

配置注册表是 view ID、分组、标签、可见条件和默认入口的单一来源，避免继续维护互相漂移的 `TOP_TABS`、`CAPABILITY_TABS`、`SETTINGS_TABS` 和 ID Set。

## 导航与状态

- 当前叶子 Tab 始终写入 `?view=`。
- 刷新、浏览器前进后退和分享链接恢复同一个叶子 Tab。
- 点击一级“配置”时，若当前已位于配置页则保持当前 Tab；否则优先回到本次访问过的配置 Tab，没有记录时进入“数字员工”。
- 原 `view=identity` 链接和 OAuth 回跳统一迁移到 `view=digital_employee`。
- `inbound` 从有效 view ID 中移除；其他有效 view ID 尽量保持不变，减少深链和测试迁移范围。
- URL 指向无权限或当前运行时不支持的 Tab 时，回退到该分组第一个可见 Tab；分组无可见项时回退到“数字员工”，并用 replace 修正 URL。
- Tab 可见性在能力查询加载过程中沿用当前避免闪烁的策略。

## 未保存与错误处理

- 所有可编辑 Tab 通过统一 dirty contract 向详情容器报告未保存状态。
- 点击一级导航、配置分组、配置 Tab、浏览器返回或关闭页面时都使用同一套离开确认。
- 保存失败保留当前草稿；错误在字段附近或当前 Tab 内显示，并使用现有 toast 作为补充反馈。
- 身份绑定错误留在对应身份卡片内，不把一张卡片的错误提升为整个“数字员工”页不可用。
- 某个条件能力加载失败时，不影响其他配置组和日常查看页面。

## 响应式行为

桌面端使用固定宽度、完整展开的配置侧栏和独立内容滚动区。

窄屏不平铺全部配置 Tab，仍使用两级选择：

1. 选择分组。
2. 选择该分组中的当前 Tab。

页面仍显示当前 Tab 标题，选择控件使用原生按钮 / 弹出菜单语义并支持键盘和可见焦点。

## 测试策略

### 单元与组件测试

- 配置注册表：分组顺序、默认 Tab、view 到分组映射、条件可见性。
- 一级导航：只显示 4 个入口，“对话”“能力”“设置”不再出现。
- URL：直接打开每个有效 `view`、刷新、前进后退和隐藏 Tab 回退。
- 配置目录：桌面端五组全部展开，无折叠按钮；切换 Tab 不改变其他分组的可见性。
- dirty guard：顶部 Tab、配置 Tab、返回和关闭页面均拦截未保存草稿。
- `DigitalEmployeeTab`：主开关始终可见；关闭时不展示 persona、reply tone 和完成后跟进，开启时展示；会话续接始终可见。
- 全局导航：智能体直接作为一级入口；不存在“智能体与小队”“扩展”和“连接”；“我的电脑”替代“本机 Runner”。
- `RobotConnectionsTab`：包含 Bot 和派发配置；不包含数字员工账号或企业身份。
- `RuntimeTab`：包含运行参数和 GitHub 沙箱身份；不包含数字员工身份。
- 权限与功能开关：只读、MCP 支持、MCP 应用、OpenClaw 路由、云端 LLM Trace。
- 响应式导航：窄屏只显示两级选择器，不产生横向 Tab 溢出。

### 验证

- 运行 `packages/views` 中智能体相关 Vitest。
- 运行 TypeScript typecheck。
- 在本地 Web 页面验证桌面和窄屏布局。
- 对比预发页面，确认原有保存、身份绑定、机器人绑定和 OAuth 回跳仍可到达正确位置。

## 验收标准

1. 智能体、小队、运行时、我的电脑和 Skills 在全局左栏直接显示；不再出现折叠分组和“连接”。
2. 智能体详情一级导航固定为“概览、工作、记忆、配置”，旧 `view=inbound` 回到概览。
3. 配置默认进入“数字员工”，桌面配置侧栏的 5 组及其子项全部展开。
4. “入站先判断”位于数字员工页首；关闭时人设、回复语气和完成后跟进不可见，开启后才显示。
5. “续接上一轮会话”始终可见，不错误依赖入站判断。
6. 每个现有配置能力都有唯一且可解释的入口，没有功能丢失。
7. 数字员工账号、钉钉执行身份和集团员工身份只出现在“数字员工”。
8. 钉钉 Bot、飞书 Bot、Slack 和企业微信只出现在“机器人接入”。
9. GitHub 沙箱身份只出现在“运行时”的执行身份区。
10. MCP 工具、MCP 应用、MCP 接入和 A2A 不互相合并。
11. URL 深链、条件可见性、权限和未保存保护具备自动化测试。
12. 桌面与窄屏都不产生横向 Tab 溢出。
