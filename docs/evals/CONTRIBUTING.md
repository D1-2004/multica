# 评测定义贡献规范

## 修改入口

当前页面只读取 `p0-golden.json` 和 `office-scenarios.json`。每例展示 `roles`、`verifies`、`method`；ID、标题、来源和引用为维护元数据，不添加历史通过率或运行状态。

- `roles` 写所需人员或执行角色及读取范围，不写真实账号、联系方式、令牌或业务定位符。
- `verifies` 写可观察的业务行为和判定条件，例如目标归属、权限、计数、输出内容、退出证明或唯一效果。
- `method` 写夹具前置、操作和独立验证方式；注明真实模型、真实执行、独立读回或隔离故障条件。
- `sources` 使用存在的仓内相对文件路径。禁止越界、外部路径、逃出仓库的符号链接、凭据和真实账号定位符。
- `sourceCases` 引用有效已有用例；`existing` 必须有来源引用，`defined` 可为空。来源存在不表示当前可运行。

P0 固定 20 个 ID `G01`–`G20`，`priority=P0`。`scenarioRefs` 声明组合涉及的场景；每个 `caseRefs` 必须存在，并属于组合声明的某个场景。只引用该组合确实执行的步骤，不用整个场景名称冒充覆盖所有反例。

## ID 与行为约束

场景和用例 ID 为全局唯一的 kebab-case。已有 ID 保留其行为身份和场景归属；更正条件、标准答案、资源前置或核验步骤可直接修订。新行为风险使用新 ID，不删除旧 ID 后复用，也不把既有用例默认移动到另一个场景。必要的移除或搬移需单独定义可审计的迁移及兼容策略，更新检查合同。

每条新用例至少关联一个实际行为风险，写进 `verifies` 和 `method`。仅更改编号、人物别名、随机码或相同有效输入数值，不算新增风险。新的权限边界、状态转移、并发顺序、来源归属、交付合同或恢复窗口可分别建立用例。每条方法必须能区分预期行为与至少一个错误行为。

自动检查能验证非空字段、重复行为文本、ID 保留、引用和来源；它不能判断所有语义差异。评审者需核对新增风险、现有覆盖和维护成本。检查将忽略标题、合成角色别名与数字，拒绝验证目标和方法完全相同的复制项；它不把正常修改既有条件判为复用。

## 从失败到回归

1. 保存失败来源和部署/配置窗口，脱敏后提取最小触发条件；保留旧历史、参与者或运行状态等必要前提。
2. 在对应场景复用原行为 ID，或为新风险创建稳定 ID。把标准答案、授权范围、来源和通过条件写入定义。
3. 分别记录 fixture 就绪条件、runner 是否能执行、证据采集方式；没有可用入口的定义仍标 `defined`，不伪造运行结果。
4. 重要链路进入或修订一个现有 P0 组合，更新真实 `scenarioRefs` / `caseRefs`，不增加第 21 条 P0。
5. 在获准环境实际运行时另存证据及结论。缺身份授权、真实读取、运行资源或完整观察窗口时记录 `blocked` / `incomplete`；不计为通过。

实际运行记录可放在 `docs/evals/results/` 或当前波次的受控证据目录。至少区分：定义 ID、fixture 条件、runner/资源就绪性、版本与运行窗口、用户效果、业务状态、模型/工具事实及结论。秘密与真实账号不写入定义；证据中的对象关联按所在目录的脱敏和访问规则保存。

静默需要 admission/job 已结算且零发送/任务效果；停止需要实际进程退出及跨过旧完成时刻的观察；文件需要消息自身资源、接收者下载和内容校验；幂等需要来源/账本/实际效果联合计数。工具返回成功、模型正文或没有看到消息，都不能单独作为真实通过证据。

## 提交与 PR 清单

- [ ] 变更只覆盖当前改动；现有稳定 ID、场景归属与授权语义保留。
- [ ] 新例写清至少一个独立行为风险，未以换号或换数复制现有例。
- [ ] 标题及三展示字段非空；来源存在且不越界，不含凭据、真实账号或业务定位符。
- [ ] `origin` 与 `sourceCases` 准确；P0 引用存在且归属声明场景。
- [ ] fixture、runner 可运行性和实际证据分别说明；仅定义的提交不宣称真实通过。
- [ ] 执行 `python3 scripts/check-eval-catalog.py --base-ref <base-commit-sha>`，记录检查结果。
- [ ] 涉及页面/后端代码时完成相应范围检查；真实 E2E 只在已经授权的范围运行。
- [ ] PR 写清新增/修订的行为风险、相关 case/P0 ID、验证范围和未具备的执行条件。

## CI 范围

`Eval catalog / definitions` 使用 Python 标准库检查两套 canonical 定义，并用 PR base SHA 或 push before SHA 做只读稳定 ID 对比。首个发布没有对应历史文件时允许初始化；当前定义文件缺失仍失败。CI 不运行真实模型、DWS 或故障演练，绿灯仅表示定义结构与引用合规。

相关 JSON、检查器、页面代码及评测规则变更触发独立工作流。要作为合并门禁，仓库管理员还需将该检查设为 required status check；此贡献规范不表示分支保护已经配置。
