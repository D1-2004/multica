# 开发与有界交付合同

适用于本项目所有开发者与编码代理。入口为 `AGENTS.md`，工程硬约束为 `CLAUDE.md`，模块合同补充领域行为，专项skills提供操作方法。个人记忆不成为项目规范；分支、checkout、账号、profile和发布目标从本次任务解析。

## 1. 开始前明确四件事

在现有任务或Plan记录下列内容。局部小改可用简短清单，不新增形式化文档；跨模块、状态机或核心链路使用Plan。

| 内容 | 必须能回答的问题 |
| --- | --- |
| 验收标准 | 用户最终得到什么；哪些失败不能接受；凭什么判定完成？ |
| E2E场景 | 从什么真实入口触发，经过哪些关键边界，最后观察什么用户结果；最小成功路径和关键失败反例是什么？ |
| 测试环境 | 需要本地/集成/预发中的哪层；固定哪些版本、配置、权限、数据、身份和外部依赖；谁负责恢复？ |
| 交付流程与边界 | 实现、验证、发布、证据和交接有哪些里程碑；本轮范围、负责人、时间预算或停止条件是什么？ |

从上下文足以确定时直接填写。关键环境或验收缺口影响正确性时及时提出，并继续独立工作；不在未明确判据的情况下不断加代码或加测试。

## 2. E2E证明目标行为

功能交付以对应用户路径的端到端证据为核心，测试覆盖取决于改动风险，而不是固定跑全项目。纯文档、仅元数据等不影响运行行为的改动或单独的源码审查可说明E2E不适用及理由；这不等于相关产品功能通过。

- 每例先定义入口、前置、操作、用户结果、关键状态/权限/副作用、失败反例和证据面。需要实际工具执行时，正确答案不代替真实执行。
- 单元/合同测试与review检查局部风险；mock不证明外部连通，编译不证明行为，模型自述/ACK不证明执行或投递。
- 模型选择、消息投递、并发恢复、跨系统状态等必须检查实际关键边界。使用可控环境和确定性夹具时标明真实与模拟边界，不冒称生产验证。
- 优先复测原失败和受影响路径。代码/合同/配置/前置仍等价的有效证据可以复用；部署变化只重测受到影响的项。
- 长等待、跨日、真人或外部资源不可用时，保存检查点并给出替代验证能够证明的部分与未证明项。不得自动用review签成E2E通过。若需改变最终验收标准，应有明确的任务范围变更。

缺环境、缺证或阻断与产品失败分别记录；安全、权限、数据完整性和关键归属失败不能被平均质量或速度抵消。已知真实失败保留，不能通过换场景、清历史或改口径消除。

## 3. 按里程碑交付

推荐工作链路：明确合同与环境 → 实现最小完整切片 → 定向检查/E2E → 按任务范围发布并核实生效 → 整理结论与恢复/交接。操作顺序随实际依赖调整，文档review或只读调查不会自行触发部署。

每项分别记录 `implemented`、本地验证、部署、E2E与最终验收结论。维护一个当前状态入口，已有任务/Plan/执行表任选适用载体，不强制新增表或固定路径。历史记录与报告引用这个入口，版本变化、失败、阻断、完成或交接时及时更新。

新增发现记录影响、位置、反例及下一步，判断是否阻断本次验收。相关核心缺陷必须说明并修复或阻断签收；其他能力列为后续范围，不自动加入无界重构/构建/发布循环。观测工具和Runtime修复与产品效果分别记录，缺某面只限制依赖它的结论。

共享测试/发布环境明确当前操作负责人及使用窗口；独立开发、review与只读取证无需等待共享写操作。保护其他人的未提交工作，分支及工作目录由任务决定，不绑定某位开发者的个人环境。

## 4. 长任务有检查点，并尽早可接手

开始时确定里程碑预算和检查点；没有用户硬截止时按任务规模估计并报告可交付边界，不套固定分钟数。到检查点评估剩余风险、环境等待、新增范围和独立进展。

出现长外部等待、需要新增权限/范围、连续相同阻断或预计超预算时，先产出可审查切片与接手包，再说明需要的下一步。不要只反复输出“继续推进”。不为制造完成率跳过关键验收，也不把待验代码称为可用版本。

人工接手可以发生在任务完成前；交接应至少包含：

```text
目标与当前结论：已实现/已验证/失败/未证明
定位：代码版本、工作目录、改动范围、未提交内容
环境与状态：必要对象、运行中的任务/测试、配置变更和恢复责任
证据与检查点：精确case/Task/Run/trace、文件指针、已完成及未到期步骤
下一步：最短接续动作、预期结果、阻断与权限需求
所有权：谁接手、有哪些锁/场域/后台操作需要转交或停止
```

明确截止到期应交付当前结论与交接，不自行创建续跑。恢复临时配置、释放场域/资源或清楚转交责任；恢复失败不得谎报完成。有后台写操作未结束时记录其确切状态与所有者，避免失控地重发或强行取消。

## 5. 效率与最小上下文

只读当前问题需要的模块和skill；批量读取独立事实，按精确ID取证，复用无变化的manifest。外部动作仍做使用时权限/目标检查，不能因缓存跳过安全门。

并行任务先给完整输入、所有权、环境、验收和交付物；是否并行由独立性与收益决定，不默认启动很多代理。业务窗口结束及时释放场域，纯取证不继续占用。轮询有界并退避；同参数失败不无限重试，不因查询超时重复触发CI。

效率衡量包括尽早出现可接手成果、减少重复取证和范围漂移，同时检查用户效果、归属与安全质量。请求数、token或墙钟只能定位瓶颈，不能代替交付质量。
