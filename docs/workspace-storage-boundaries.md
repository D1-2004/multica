# 工作区存储边界

系统有两类独立存储域。共享盘授权不改变员工私有盘，也不是 DSH Profile 的权限。

## 共享盘

任务挂载路径是 `/mnt/workspace/shared`。权限按智能体配置为 `none`、`read` 或 `write`，分别使用该工作区的只读卷、只读写卷和对应的复合角色。

用户期望的授权和这一次启动实际生效的权限分开记录。只读卷还挂着时，把授权从 `read` 扩成 `write` 不会拆掉健康沙箱；这次任务仍然声明 `read`。正常重建并确认挂上可写卷之后，才声明 `write`。

已经确认的授权约束不依赖新卷或新角色是否准备好。复合角色还没准备好时，不能把已经收成 `read` 的约束丢掉，也不能把仍挂着可写卷的沙箱交给新的只读任务。没有共享挂载的健康沙箱可以继续运行。云资源开通不在任务启动的关键路径上。

## 员工私有盘

挂载路径是 `/mnt/multica`。对该员工的运行时，私有盘默认可读写。`DSH_HOME=/mnt/multica/home`。安装后的插件构建产物位于 `/mnt/multica/plugin-builds`。

双挂载使用的复合角色必须保留私有盘原有的读写能力。共享盘从 `write` 收到 `read`，或者暂时没有复合角色，都不改变 `/mnt/multica` 的权限。

## 界面

共享盘只出现在「文件」页和智能体「文件系统」页。DSH 配置里只有员工私有盘，不放共享盘的授权、目录或路径。

## 和 DSH 的关系

插件、Profile 和沙箱寿命沿用各自原有的语义。沙箱启动续期下限、任务结束后的宽限和空闲保留时间不由共享盘授权改变。

只有某一条共享盘状态转换会退役、重建或阻塞承载 DSH 的沙箱时，才把这件事记成对 DSH 的间接影响，并写明调用链。普通的共享盘故障和扩权不走退役。
