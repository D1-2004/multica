# Coordinator 上下文减重与终结校验

## 问题与范围

正式trace `605e116e29704bf294f653bb4508a684`（policy 2026-09-08.5）将AI听记机制查证直接回答为“只生成一份”；只调用assoc_recall和finish，没有派发。初始user prompt 17681字符，其中完整岗位块16336；旧finish只检查少数假完成措辞。

用户授权修改、提交推送并部署预发。沿用不做E2E的限制；冻结trace的真实模型回放仅使用假只读工具，不写任务、不发消息。

## 实现选择

1. 快循环不再默认重复展开完整执行岗位SOP；保留完整Turn.Instructions及其hash/长度，用于按需工作约束读取、直接终结审查和既有执行器上下文。不能通过截断丢掉末尾的授权/隐私限制。
2. 收紧并精简内建路由规则：业务分析/产品知识查证属于执行器，召回事项只建立目标/进度证据；问候、澄清、能力说明、记忆盘点、已核实进度仍可直接回复。
3. 模型生成的reply/silence，以及带非空自定义岗位说明的issue计划，在SavePlan之前进行独立有界终结审查，输入完整岗位限制、原始窗口和已读证据。直接回答检查无依据业务结论/漏工作；issue只核计划授权、范围和承诺，不要求执行前先有业务答案。检查失败不放行、不自动创造执行授权。task_finished沿用独立完成合同。
4. 替换旧“一次假完成hint后放行”的保护；保留同run审查缓存防止重复无效答复消耗审查请求；审查生成/裁决可在LF与SLS定位。
5. 同步policy/Host/schema/来源与正反例，验证真实事故、问候/澄清/状态/场域记忆/授权末尾限制等对照，并量化快循环上下文变化。
6. 提交推送原工作分支，复用或新建精确CR发布预发；冲突按语义处理，核对构建SHA、部署和健康。仅应用预发，不推进正式或人工验收门禁。

## 验证与风险

- 窄Host测试验证拒绝后无SavePlan、允许回复、审查错误不放行和终结流程不重入。
- 规则结构检查仅证明来源与版本闭合，真实冻结回放单独记录；不把无副作用回放称为E2E。
- 直接终结以及有自定义岗位的工作计划增加一次有界审查；完整SOP从每轮重复改为审查一次。需报告时延及token，不宣称LLM判断绝对正确。
- 完整岗位约束不做启发式摘要或硬截断，避免丢失安全/业务边界；暂不引入跨副本缓存/数据库迁移。

- 真实冻结回放：7例全部通过；原产品问题、已核实进度、仅起草授权边界各追加2轮，全部通过。原问题三次均产生新lookup issue计划，无旧事项续接；仅fake只读工具，没有创建任务或发送消息，不能称E2E。
